# E5 前端契约：页面、接口消费与交互状态

本契约自 E5 起生效，约束 `web/` 下的全部前端代码。**后端接口一个字节都不改**：本契约只规定"前端如何消费已冻结的接口"。

E6（PWA 与移动端适配）在本文之上追加清单与缓存策略，不得改动本文的页面数量、令牌存放位置与状态机。

## 一、页面清单：固定 2 页 + 2 弹层

| 页面 | 文件 | 职责 | 明确不做 |
| --- | --- | --- | --- |
| 登录页 | `web/login.html` | 输入口令、显示登录失败原因、成功后进入列表页 | 注册、找回口令、"记住我"、多账号 |
| 设备列表页 | `web/index.html` | 展示设备与状态、唤醒、编辑、删除、退出登录 | 设备详情页、历史记录、日志、设置 |

| 弹层 | 载体 | 触发 |
| --- | --- | --- |
| 编辑弹层 | `<dialog id="editor">` | "添加设备"按钮、卡片上的"编辑" |
| 删除确认 | `<dialog id="confirm">` | 卡片上的"删除" |

弹层不是页面：不产生新 URL、不新增 HTML 文件、不写入浏览器历史。**页面数量是验收项 5-4 的硬指标**，`ls web/*.html` 必须恰好 2 个。

## 二、令牌

| 项 | 规定 |
| --- | --- |
| 唯一存放位置 | `localStorage["wol.token"]`，字符串，值为登录响应的 `token` 原样 |
| 注入方式 | 每个请求的 `Authorization: Bearer <token>`，请求时从该键读取 |
| 禁止位置 | Cookie、`sessionStorage`、URL 查询参数、IndexedDB、页面变量长期持有 |
| 退出登录 | 先调 `POST /api/logout`，无论成功失败都清空该键并回登录页 |
| 过期处理 | 见第五节；清空该键是唯一动作，不保留"上次登录"信息 |

令牌是明文 Bearer，服务按局域网直连设计。**不提供加密存储**：加密密钥只能放在同一份前端代码里，属于自欺欺人。

## 三、接口消费清单

前端只调用下表 9 个接口，不新增、不绕过、不并行改造：

| 方法 | 路径 | 调用时机 | 使用的响应字段 |
| --- | --- | --- | --- |
| POST | `/api/login` | 登录页提交 | `token`、`expires_at` |
| POST | `/api/logout` | 点"退出" | 无（204） |
| GET | `/api/devices` | 进入列表页、保存后、点"刷新" | 9 个字段全部原样使用 |
| POST | `/api/devices` | 编辑弹层新增保存 | `id`（仅用于重新拉取前的定位） |
| PUT | `/api/devices/{id}` | 编辑弹层修改保存 | 同上 |
| DELETE | `/api/devices/{id}` | 删除确认 | 无（204） |
| POST | `/api/devices/{id}/wake` | 点"唤醒" | `sent`、`sent_at` |
| POST | `/api/devices/{id}/check` | 唤醒成功后立即触发 | `status`、`started_at` |
| GET | `/api/status` | 校验中每 5 秒轮询 | `device_id`、`status`、`message`、`checked_at` |

`GET /api/health` 本环节不使用（属容器探活）。

### 字段使用规则（5-5）

1. **不改名**：`broadcast_addr` 不写成 `broadcast`，`probe_value` 不拆成 `host` + `port`。
2. **不重组**：设备卡片的状态来自 `/api/status`，**不写回** `/api/devices` 的响应，也不在前端合并成新的"设备+状态"对象落盘。
3. **不补字段**：请求体只包含契约列出的 6 个键（`name`、`mac`、`broadcast_addr`、`broadcast_port`、`probe_type`、`probe_value`），不发 `id`、不发时间戳。
4. **`probe_type` 为 `none` 时**，`probe_value` 固定传空串（与 E1 契约一致）。
5. **时间戳只做显示格式化**（RFC3339 → `YYYY-MM-DD HH:mm:ss`），不改变语义、不做时区换算以外的运算。

## 四、错误码 → 界面文案

文案规则：**一句话说明问题 + 下一步动作**。服务端已给出具体字段说明的 400 类错误直接透传，前端不另造一套。

| `error` | HTTP | 界面文案 | 位置 |
| --- | --- | --- | --- |
| `invalid_credentials` | 401 | 口令错误，请重新输入 | 登录表单内 |
| `too_many_attempts` | 429 | 尝试次数过多，请约 10 分钟后再试 | 登录表单内 |
| `invalid_json` / `invalid_name` / `invalid_mac` / `invalid_broadcast_addr` / `invalid_broadcast_port` / `invalid_probe` / `invalid_id` | 400 | 直接显示服务端 `message` | 编辑弹层内 |
| `not_found` | 404 | 设备不存在，可能已被删除，请刷新列表 | 页内提示条 |
| `duplicate_mac` | 409 | 该 MAC 已被其他设备使用，请检查后重试 | 编辑弹层内 |
| `limit_exceeded` | 409 | 设备数量已达上限，请先删除不再使用的设备 | 编辑弹层内 |
| `check_in_progress` | 409 | 该设备正在校验中，请等待本次结果 | 页内提示条（继续轮询） |
| `send_failed` | 500 | 唤醒包发送失败，请检查广播地址与当前网络 | 页内提示条 |
| `unauthorized` / `token_expired` | 401 | **不提示**，直接回登录页 | —— |
| 其他 5xx | 5xx | 服务暂时不可用，请稍后重试 | 页内提示条 |
| 网络层失败（`fetch` 抛错 / 超时） | —— | 无法连接服务，请确认服务正在运行、手机与主机在同一局域网，然后重试 | 页内提示条 |

禁止把 `HTTP 500`、`TypeError`、堆栈、接口路径直接展示给用户（5-7）。

## 五、401 与防循环（5-3）

```
任一受保护请求返回 401 且 error ∈ {unauthorized, token_expired}
  → 置"正在跳转"标记（同一页面生命周期只跳一次）
  → 清空 localStorage["wol.token"]
  → location.replace("login.html?reason=expired")
登录页检测到 reason=expired
  → 清空令牌（幂等）
  → 在表单上方显示一次"登录已过期，请重新输入口令"
  → 不弹 alert、不自动重试、不再跳转
```

防循环的三道闸：一次性跳转标记、跳转前清令牌、登录页不再自动跳回列表页（携带 `reason` 时）。

登录页在**无** `reason` 且本地已有令牌时直接进入列表页；若该令牌其实已失效，列表页首个请求会带着 `reason=expired` 跳回来，此时令牌已被清除，链路终止。

## 六、唤醒状态机

界面状态与服务端五态的对应关系：

| 界面状态 | 进入条件 | 按钮 | 卡片状态标签 | 离开条件 |
| --- | --- | --- | --- | --- |
| 空闲 | 初始 / 终态后 | "唤醒"可点 | 按 `/api/status` 显示 | 点击唤醒 |
| 发送中 | 点击唤醒，`POST /wake` 进行中 | 禁用，"发送中…" | "发送中" | 202 返回 → 校验中；失败 → 空闲 + 提示 |
| 校验中 | `POST /check` 已受理 | 禁用，"校验中…" | "校验中" | 轮询到终态；或超过 130 秒 |
| 已上线 | 轮询到 `online` | "唤醒"可点 | "已上线" | —— |
| 超时未响应 | 轮询到 `timeout` | "唤醒"可点 | "超时未响应" | —— |
| 校验失败 | 轮询到 `failed` | "唤醒"可点 | "校验失败" | —— |

规则：

- 轮询间隔 **5 秒**，与后端探测间隔一致；客户端上限 **130 秒**（后端 120 秒 + 10 秒余量），超限即停止轮询并提示"点刷新查看最新状态"。
- 多个设备可同时处于校验中，共用一个轮询定时器，无任务时定时器必须停止。
- `POST /check` 返回 `409 check_in_progress`：视为已在校验中，继续轮询，不报错。
- `POST /check` 返回 `400 invalid_probe`：停止流程，提示"唤醒包已发送，但校验未能启动：…"，状态退回"待校验"。
- `probe_type = none`：不调用 `/check`，提示"唤醒包已发送。该设备未配置校验目标，无法自动确认是否开机。"
- **`POST /wake` 的 202 只表示包已交给内核**，界面在收到终态前不得出现"已开机""唤醒成功"字样。

## 七、视觉与文案

- 移动优先，单列卡片流；≥ 720px 转为两列网格。最小适配宽度 360px（宽度断点验收属 E6 的 6-2）。
- 状态用"色点 + 文字"表达，不引入图标库、不使用纯颜色传达信息。
- 空态、错误态、加载态三种状态必须都有明确文案，禁止空白页。
- 所有可点元素最小高度 42px；按钮在请求期间禁用并改变文案，避免重复提交。

## 八、本环节明确不做

PWA 清单与 Service Worker、离线能力、深色模式、多语言、键盘快捷键、拖拽排序、批量操作、设备分组、历史记录与图表、消息推送、WebSocket、前端路由、构建产物与压缩。

这些不影响 5-1 至 5-7 的判定，其中 PWA 与宽度适配属 E6。
