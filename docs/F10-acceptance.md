## 二、端到端（tmp/f10-e2e.py，17/17 通过）

真实 HTTP + 真实客户端进程（演练模式）：

```
PASS 服务端启动 / 管理员登录 / 创建设备
PASS 离线设备拒绝下发(409 device_offline)
PASS 客户端心跳上报 → 设备已上线
PASS 下发关机指令(201 pending) / 重复下发被拒(409) / 非法类型(400)
PASS 客户端执行指令(演练) → 日志含 shutdown.exe 命令行
PASS 指令状态 done + 回执说明 + 送达/完成时间齐全
PASS 全局指令列表 / 非心跳设备拒绝(400) / 未登录(401)
```

回执验证了 F10 的关键时序：**客户端执行后立刻补发一次心跳送回执**（不等到下一个 60 秒周期），因为关机延时只有 60 秒，机器随时会断。

## 三、网页端（tmp/f10-ui.mjs，Chrome CDP，13/13 通过）

```
PASS 心跳设备卡片出现 重启/关机 按钮；非心跳设备不出现
PASS 点关机 → 弹层标题「关机设备」、说明含 60 秒缓冲与 shutdown /a 撤销、按钮「确认关机」
PASS 确认后卡片提示「关机指令：等待客户端取走（下一个心跳周期）」
PASS 客户端执行后刷新 → 卡片提示「关机指令：已执行」（保留 10 分钟）
PASS 重启弹层文案正确，取消不下发
PASS 下发后自动进入 5 秒轮询，终态自动停止
```

截图见 `tmp/shots-f10/`（已用 GDI/CDP 抓取核对排版）。

## 四、真实执行说明

本机验收全部使用演练模式（`WOL_SHUTDOWN_DRYRUN=1` / `--dry-run`），日志记录将要执行的完整命令行：
`shutdown.exe /s /t 60 /c "远程指令：WakeOnLAN 管理端"`。
真实关机路径与演练共用同一份代码，仅差"是否启动进程"这一个分支；目标机的实际关机在首次部署后人工确认一次即可。

## 五、遗留与注意

1. `delivered` 之后客户端若断电，指令不会重发（防重复执行），界面会一直显示"客户端已接收"——这是刻意的，宁可状态陈旧也不要机器半夜自己关机；
2. 关机后设备必然显示"心跳超时"，这是正常现象，不是故障；
3. 客户端日志在 `logs\`，服务端指令审计在 `GET /api/commands`。
