# E4 接口契约：认证与接口保护

本契约自 E4 起生效，E5 前端按此对接。**E1、E2、E3 契约中的路径、请求体、响应体一字未改**——本环节只在其外层加一道令牌校验。

## 一、免鉴权路径（白名单）

| 路径 | 方法 | 为什么必须公开 |
| --- | --- | --- |
| `/api/health` | GET | 容器 `HEALTHCHECK` 的唯一探针；加鉴权会导致容器永远不健康 |
| `/api/login` | POST | 登录入口本身不能要求登录 |
| `/`、`/index.html`、`/app.css`、`/app.js` 等静态资源 | GET | 登录页与前端资源需要先加载出来，才能输入口令 |

其余全部 `/api/` 路径一律需要令牌。白名单只有这三类，**不提供"临时关闭鉴权"的开关**。

## 二、登录

```
POST /api/login
Content-Type: application/json

{"password": "..."}
```

成功：`200`

```json
{"token": "V1StGXR8_Z5jdHi6B-myT0aBcDeFgHiJkLmNoPqRsTu", "expires_at": "2026-10-25T16:50:00+08:00"}
```

响应字段白名单恰好 2 个键：`token`、`expires_at`。不返回用户名、不返回权限、不返回刷新令牌。

- `token`：43 个字符，`base64url`（无 `=` 填充），由 32 字节 `crypto/rand` 生成。服务端只保存其 SHA-256，不保存明文。
- `expires_at`：RFC3339，签发时一次性确定，**不做滑动续期**。每次调用都不会延长有效期。

失败：

| 情况 | 状态码 | `error` | `message` |
| --- | --- | --- | --- |
| 口令错误或为空 | 401 | `invalid_credentials` | 口令错误 |
| 该来源已被锁定 | 429 | `too_many_attempts` | 尝试次数过多，请稍后再试 |
| 请求体不是合法 JSON / 含未知字段 | 400 | `invalid_json` | 请求体不是合法 JSON，或包含契约之外的字段 |

失败响应不区分"口令错"与"用户不存在"（本项目也没有用户），不返回剩余尝试次数。

## 三、令牌的使用

```
Authorization: Bearer <token>
```

- 大小写不敏感地接受 `Bearer` 前缀与令牌之间**一个**空格。
- 不接受 Cookie、不接受 `?token=`、不接受请求体中的令牌。
- 缺失、格式错误、无法匹配：`401 unauthorized`（`message`：请先登录）。
- 已过期：`401 token_expired`（`message`：登录已过期，请重新登录）。**过期与无效用不同的 `error` 值**，前端据此决定是"跳登录页"还是"提示重新登录"（E5 验收 5-3 依赖此区分）。
- 已登出：令牌被删除，再访问即为 `unauthorized`。

## 四、登出

```
POST /api/logout        （需要令牌）
```

成功：`204`，无响应体。

仅吊销**当前请求所用**的令牌，不影响其他令牌（例如另一台手机上的会话）。

重复登出的行为：第一次返回 204；之后该令牌已失效，再调用会先被中间件拦下并返回 `401 unauthorized`——这是"所有接口都需令牌"的正常结果，不视为错误，也不会产生副作用。

## 五、限流

| 项 | 值 |
| --- | --- |
| 计数维度 | 来源 IP（取 TCP 对端地址，不使用 `X-Forwarded-For`） |
| 触发阈值 | 连续失败 5 次 |
| 锁定时长 | 10 分钟 |
| 锁定期间 | 即使口令正确也返回 429 |
| 计数清零 | 登录成功即清零；锁定到期后自动清零 |

规则细节：

- 第 1–5 次错误口令返回 401，第 5 次同时写入锁定。
- 第 6 次起（锁定期内）返回 429。
- 成功登录会清空该 IP 的失败计数，不会"攒着"。
- 计数与锁定只存在内存中，**进程重启即清空**。这是刻意取舍：不在数据库里记安全事件，避免引入"登录审计"这类范围外功能。

## 六、有效期与重启

- 默认有效期 7 天，由 `WOL_TOKEN_TTL` 配置（Go duration，如 `168h`、`30m`）。非法值拒绝启动。
- 会话表在**内存**中，进程重启后全部令牌失效，需要重新登录。不落库的理由：落库就要建会话表，与"禁止用户表/账号体系"的边界太近，且家庭场景重启频率极低。

## 七、配置项（本环节新增 1 个）

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `WOL_ADMIN_PASSWORD` | 无（**必填**） | 为空时进程拒绝启动并提示注入方式 |
| `WOL_TOKEN_TTL` | `168h` | 令牌有效期，Go duration 写法，必须大于 0 |

口令不提供默认值。给默认口令等于把"没配置"变成"配置了一个所有人都知道的口令"，比不设防更危险。

## 八、错误码表（本环节新增）

| HTTP | `error` | 触发条件 |
| --- | --- | --- |
| 400 | `invalid_json` | 登录请求体非法或含未知字段 |
| 401 | `invalid_credentials` | 口令错误 |
| 401 | `unauthorized` | 未带令牌、令牌格式错误、令牌不存在（含已登出） |
| 401 | `token_expired` | 令牌已过有效期 |
| 429 | `too_many_attempts` | 该来源连续失败 5 次后处于锁定期 |

错误响应仍为统一的 `{"error","message"}` 两键结构，不追加 `retry_after`、`attempts_left` 等字段。

## 九、与既有契约的关系

| 契约 | 变化 |
| --- | --- |
| `docs/E1-contract.md` | 路径、字段、状态码**均不变**；调用时需带 `Authorization` |
| `docs/E2-contract.md` | 同上；唤醒接口需令牌 |
| `docs/E3-contract.md` | 同上；触发校验与状态查询需令牌 |
| `/api/health` | **不变，且保持公开** |

## 十、明确不做

| 不做项 | 理由 |
| --- | --- |
| 用户表、账号、注册、找回密码、改密 | 单用户自用，口令在环境变量里；引入即扩大开发 |
| 刷新令牌、滑动续期 | 7 天到期重新登录，成本可接受 |
| 多会话管理、在线设备踢出 | 无界面、无需求 |
| Cookie 会话、CSRF 防护 | 不用 Cookie，令牌在请求头里，无 CSRF 面 |
| HTTPS、证书、HSTS | 属部署与网络边界，E7 文档提示"勿暴露公网" |
| 登录审计、失败记录表 | 排除清单内的"操作日志" |
| 验证码、二步验证 | 家庭局域网场景不适用 |
| 前端登录页 | E5 |
