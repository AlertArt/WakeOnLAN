# E2 接口契约（冻结）

本文件定义 F2 一键唤醒的 HTTP 接口。设备 CRUD 的字段与错误码见 `docs/E1-contract.md`，本文件不重复。

## 通用约定

沿用 E1：成功响应直接返回对象，失败响应固定为 `{"error":"<码>","message":"<中文说明>"}`。

## 接口

```
POST /api/devices/{id}/wake
```

请求体：**无**。服务端从设备记录中读取 MAC、广播地址、广播端口，不接受客户端传入。

响应 202：

```json
{"sent": true, "sent_at": "2026-10-18T10:52:31+08:00"}
```

字段白名单（**只允许这 2 个键**）：

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `sent` | bool | 恒为 `true`；失败走错误响应，不会出现 `false` |
| `sent_at` | string | 包交给内核的时间，RFC 3339 |

为什么是 202 而不是 200：`sent` 只代表「102 字节 UDP 包已交给内核」，设备是否真的开机由 E3 的探测判定。202 表达「请求已受理，结果待确认」，不给调用方「设备已唤醒」的错觉。

## 错误码

| HTTP | `error` | 触发条件 |
| --- | --- | --- |
| 400 | `invalid_id` | 路径 ID 不是正整数 |
| 404 | `not_found` | 设备不存在 |
| 500 | `send_failed` | 本机网络不可用或发送失败 |

`send_failed` 附带 `message` 说明原因，但不回显系统调用细节。

## 明确不做

| 不做项 | 原因 |
| --- | --- |
| 请求体传 `mac` / `broadcast_addr` | 设备记录是唯一事实来源，避免客户端与库内配置不一致 |
| 返回 `device` 完整对象 | 前端在列表里已有该数据，重复返回会诱导前端把唤醒响应当作设备快照 |
| 重试参数、发送次数、间隔 | 已列入 E2 禁止事项 |
| 探测结果、`status` 字段 | 属 E3 |
| 批量唤醒 `/api/wake-all` | 一期排除清单内 |
