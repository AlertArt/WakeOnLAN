# E0 技术选型说明

只陈述选了什么，不在本文件论证"为什么不用别的"。

## 结论

| 维度 | 选择 | 一句话说明 |
| --- | --- | --- |
| 语言与版本 | Go 1.24 | 单二进制产出，便于交叉编译 amd64 / arm64 |
| HTTP | 标准库 `net/http`（含 Go 1.22+ 的带方法与通配符路由） | 接口数量小，无需框架 |
| 存储 | SQLite，驱动 `modernc.org/sqlite`（纯 Go，免 CGO） | 单文件数据库，部署时挂载一个卷 |
| 日志 | 标准库 `log/slog` | 结构化输出，够用 |
| 前端 | 原生 HTML / CSS / JS，无构建链，由后端同端口托管 | 两页应用，不引入构建工具 |
| 配置 | 环境变量，统一前缀 `WOL_` | 与容器部署方式一致 |
| 部署 | 单容器；数据目录 `/data` | 一条命令启动，数据落卷 |
| 测试 | Go 标准 `testing` + `httptest` + 临时目录 SQLite | 不引入测试框架 |

## 目录与命名约定

- 进程入口：`cmd/wold/`
- 内部包：`internal/{config,store,httpapi,wol,probe}`
- 静态资源：`web/`
- 部署文件：`deploy/`
- 端到端脚本：`test/e2e/`
- 环节文档与验收记录：`docs/`

命名约定：

| 对象 | 约定 | 示例 |
| --- | --- | --- |
| 接口前缀 | `/api/` | `/api/health` |
| 数据表名 | 单数小写下划线 | `device` |
| 环境变量 | `WOL_` + 大写下划线 | `WOL_PORT` |
| 数据文件 | `wol.db`（位于数据目录） | `/data/wol.db` |

## E0 已落地的内容

- 可启动的最小服务：环境变量解析 → SQLite 打开与自检 → HTTP 服务 → 优雅退出。
- 唯一接口：`GET /api/health`，返回 `status` / `db` / `time`；数据库不可用时返回 503。
- 静态托管：`web/index.html` 占位页（读取健康检查并展示状态）。
- 单元测试：配置解析 4 项、存储连通 2 项、健康检查 3 项。
- 依赖清单：`docs/E0-dependencies.md`。
