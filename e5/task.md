# 本环节任务单（E5 前端设备管理与唤醒交互）

## 环节

E5 —— 前端设备管理与唤醒交互。

## 功能范围

仅 F4（状态展示）与 F6（响应式界面）中的页面部分：登录页、设备列表页、编辑弹层、唤醒按钮状态机、接口调用封装、错误提示。

不涉及 PWA 清单与离线能力（E6）、不涉及 Docker（E7）、不涉及端到端验收脚本（E8）、**不新增任何后端接口**。

目标是"在两屏之内完成看设备—点唤醒—看结果"，不是做一个后台管理系统。这句话决定了本环节应该做得**多小**。

## 背景

后端 E1–E4 已冻结，10 个接口有 139 个用例守着。前端是本项目第一次"用户能看见"的交付，也是 Agent 最容易越界的地方：一旦引入组件库、框架或状态管理，代码量翻倍，还会顺手加一个设置页、一个关于页、一个设备详情页。

本环节的纪律是**只消费、不改造**：接口路径、请求体、响应字段一个字都不动，页面数量固定为两页，编辑与删除确认都用弹层。

## Agent 输入

- 页面：登录页 + 设备列表页，共 **2 个 HTML**；编辑用 `<dialog>` 弹层，删除用确认弹层。
- 接口：只消费 `docs/E1`–`E4-contract.md` 已登记的接口；字段原样使用，不改名、不重组、不落盘。
- 令牌：登录响应的 `token`，只存 `localStorage` 单个键 `wol.token`，不写 Cookie。
- 交互状态：空闲 / 发送中 / 校验中 / 已上线 / 超时 / 失败，取值与 `E3-contract.md` 的五态一一对应。
- 文案规范：一句话说明问题 + 下一步动作；不出现开发者调试信息。
- 契约见 `docs/E5-contract.md`（本环节冻结，E6 在此之上加 PWA）。

## 允许改动的文件

- `web/`（`login.html`、`index.html` 重写为列表页，新增 `app.css`、`app.js`、`login.js`、`devices.js`）
- `docs/E5-contract.md`、`docs/E5-acceptance.md`、`e5/task.md`、`README.md`

**不修改** `internal/`、`cmd/`、`go.mod`、`go.sum`。本环节不产生任何 Go 代码变更。

## 禁止事项

1. **禁止修改后端任何文件与接口契约**。请求体与响应字段一字不改；发现字段不够用，记录到"未做清单"，不得自行加字段。
2. **禁止引入构建链与第三方运行时**：webpack/vite/tsc、React/Vue/Svelte、UI 组件库、图表库、状态管理、CSS 预处理器、CDN 外链，一律不允许。零依赖、零构建、直接刷新生效。
3. **禁止新增页面**：设置页、关于页、帮助页、日志页、设备详情页都不做。HTML 文件数固定为 2。
4. **禁止为了让前端好写而新增接口**，例如 `/api/me`、`/api/summary`、`/api/status/{id}`、`/api/devices/{id}/wake-and-check`。编排在前端完成，不改契约。
5. **禁止令牌出现在第二处**：不写 Cookie、不写 URL 查询参数、不写 `sessionStorage`；只允许 `localStorage["wol.token"]` 一个键。
6. **禁止把接口数据缓存到浏览器存储**（令牌除外）。刷新页面必须重新拉取，不允许展示上次的陈旧状态冒充最新。
7. **禁止发明第六种状态，禁止改状态文案的含义**：`timeout` 必须显示为"超时未响应"，不得显示为"失败"；`failed` 才叫"校验失败"。
8. **禁止硬编码设备、示例数据、假状态**。空列表必须显示空态说明，而不是塞两条演示设备。
9. **禁止承诺"已开机"**。唤醒接口 202 只代表包已发出，界面文案必须区分"唤醒包已发送"与"已上线"。
10. **禁止离线队列、后台同步、WebSocket/SSE 推送**。轮询是唯一的结果获取方式。
11. **禁止在页面上暴露 HTTP 状态码、堆栈、`console.log` 调试输出**。

## 输出要求

1. 文件：
   - `web/login.html` + `web/login.js`：口令登录、失败提示、成功后进入列表页；已被过期踢回时给出一次说明，不弹窗。
   - `web/index.html` + `web/devices.js`：设备卡片列表、状态标签、唤醒、编辑弹层、删除确认、退出登录、空态与错误提示。
   - `web/app.js`：令牌存取、`fetch` 封装（令牌注入、401 跳转、错误文案）、状态文案表、时间格式化。
   - `web/app.css`：移动优先的响应式样式，最小适配 360px（正式宽度验收属 E6）。
2. 关键行为：
   - 未登录进入列表页 → 直接跳登录页；登录成功 → 进入列表页。
   - 任一受保护接口返回 `401 unauthorized` / `401 token_expired` → 清令牌并回登录页，**只跳一次**。
   - 唤醒：按钮"发送中…" → 触发校验 → "校验中…"（5 秒轮询）→ 终态（已上线/超时未响应/校验失败），按钮恢复可点。
   - 未配置校验目标的设备：只发唤醒包，明确提示"无法自动确认是否开机"，不启动轮询。
   - 任何请求失败：页内文案提示 + 按钮恢复可点，不白屏。
3. 文档：`docs/E5-contract.md`（契约）、`docs/E5-acceptance.md`（5-1~5-7 证据 + 可点击的操作路径说明）。

## 验收方式

按开发计划 4.6 节 5-1 至 5-7 执行，结果记录在 `docs/E5-acceptance.md`：

```bash
go vet ./... && go test ./...        # 后端 139 个用例必须仍全绿（本环节不碰后端）
ls web/*.html                        # 必须恰好 2 个
grep -rn "cdn\|unpkg\|jsdelivr\|googleapis\|<script src=\"http" web/
grep -rn "localStorage\|sessionStorage\|document.cookie" web/
grep -rniE "lorem|TODO|FIXME|console\.(log|debug)|占位" web/
git diff --stat -- internal cmd go.mod go.sum    # 必须为空
```

**5-1、5-2、5-3 必须真机实测**（浏览器打开页面走真实路径、真实断网），不接受代码阅读或单元测试代替。

## 完成定义

5-1 至 5-5、5-7 全部通过；5-6 为零第三方依赖（零命中）；`web/` 下恰好 2 个 HTML；后端 `go test ./...` 139 个用例全绿；`git diff` 中 `internal/`、`cmd/` 无改动。
